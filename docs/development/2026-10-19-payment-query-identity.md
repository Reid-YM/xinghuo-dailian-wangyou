# 主动查单交易身份校验

## 问题与行为

主动查单以前直接根据返回的 trade_state 分支处理。SUCCESS 路径虽校验商户和金额，但没有确认返回 out_trade_no 等于本次查询的支付单号，可能操作另一笔本地支付单；CLOSED 路径也没有先校验响应身份。关闭前的查单存在相同缺口。

两个入口统一在处理状态前校验：响应非空、交易状态存在，且 mchid、appid、out_trade_no 分别匹配当前配置和本次查询支付单。缺失或不匹配时拒绝并保留本地状态，不调用微信关闭，不写入收款流水。成功到账后的金额、币种及微信交易号校验继续保留。

微信普通商户[查单接口文档](https://pay.wechatpay.cn/doc/v3/merchant/4013070356)将 appid、mchid、out_trade_no、trade_state 列为必填应答字段。未支付或已关闭时，不要求成功到账才具有的交易号及金额字段；回归明确覆盖这种合法响应，避免误拒。

## 验证范围

- 两笔本地支付存在时，查第一笔却返回第二笔的 SUCCESS/CLOSED，两种入口均拒绝，两笔状态及流水不变。
- 商户或应用不匹配、必填字段缺失和空响应，均拒绝变更及关闭操作。
- 身份匹配的 CLOSED、NOTPAY 即使没有可选收款字段仍可正常处理。
- 既有到账幂等、退款保护、关闭状态及定时逐笔事务回归继续执行。测试 SDK 响应改为按实际查询单号返回，未放宽校验。

隔离 H2 与模拟 SDK 测试，不请求真实商户；无 migration、生产配置、权限或认证变更。回滚恢复本提交前代码会重新暴露响应与请求单号不一致的问题。本批合并和 CI 不等于生产发布。
