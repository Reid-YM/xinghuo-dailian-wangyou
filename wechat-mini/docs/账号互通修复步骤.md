# 账号互通修复步骤（服务器侧）

## 现象

用**真实 `wx.login` code**（与真机等同）调用：

```
POST https://wydlgf.cn/api/account/wechat-mini/profile
{"loginCode":"<32 位 code>"}
```

返回：

```
502 {"error":"WECHAT_SERVICE_UNAVAILABLE","message":"微信服务暂不可用，请稍后重试"}
```

请求已通过 CSRF 校验（`X-Requested-With: fetch`），失败点在**服务端调用微信 `jscode2session`** 这一步。

---

## 第一步：一条命令定位（在服务器上执行）

先进入生产 `.env` 所在目录（通常 `/opt/xinghuo-v2` 或 `/srv/xinghuo-dev/work/xinghuo-v2`）：

```bash
# 1) 只看 AppID，以及密钥的前 4 位（避免密钥泄露进聊天记录/日志）
grep -E '^WECHAT_MINI_(APP_ID|APP_SECRET)=' .env | sed -E 's/^(WECHAT_MINI_APP_SECRET=.{4}).*/\1****/'

# 2) 拿配置里的凭据直接问微信（js_code 用假值，只看 errcode）
APPID=$(grep -E '^WECHAT_MINI_APP_ID=' .env | cut -d= -f2- | tr -d '"')
SECRET=$(grep -E '^WECHAT_MINI_APP_SECRET=' .env | cut -d= -f2- | tr -d '"')
curl -s "https://api.weixin.qq.com/sns/jscode2session?appid=${APPID}&secret=${SECRET}&js_code=TEST&grant_type=authorization_code"; echo
```

## 第二步：结果判读

| 返回内容 | 含义 | 怎么处理 |
| --- | --- | --- |
| `{"errcode":40029,"errmsg":"invalid code"}` | ✅ **凭据是对的**（只是我故意传了假 code） | 问题不在密钥 → 看服务日志里真实请求的错误码；或检查服务器出网 |
| `{"errcode":40125,"errmsg":"invalid appsecret"}` | ❌ AppSecret 不正确 | 去小程序后台复制/重置正确密钥，更新 `.env` 后重启服务 |
| `{"errcode":40013,"errmsg":"invalid appid"}` | ❌ AppID 不正确 | 应为 `wx659acdb58a685b88` |
| 超时 / 无输出 | ❌ 服务器出网不通 | 检查 DNS、防火墙、代理 |

顺便看一眼服务日志里 `jscode2session` / `WECHAT_SERVICE_UNAVAILABLE` 附近的记录，能直接看到微信返回的错误码：

```bash
sudo journalctl -u xinghuo-v2.service --since '30 min ago' | grep -i -E 'wechat|jscode|mini' | tail -30
```

## 第三步：改完生效

```bash
# 1) 更新 .env 里的 WECHAT_MINI_APP_SECRET
# 2) 重启
sudo systemctl restart xinghuo-v2.service
# 3) 确认服务起来
systemctl status xinghuo-v2.service --no-pager | head -5
curl -s https://wydlgf.cn/api/account/wechat-mini/availability; echo
```

## 注意事项

- **不要把 AppSecret 贴进聊天、提交进仓库或写进小程序客户端**；我这边只需要看 `errcode`，不需要密钥本身。
- 重置密钥会让旧密钥**立即失效**，凡是用了它的地方都要同步更新（目前只有网站服务端）。
- 本次只涉及服务器 `.env` 与重启，**不涉及代码改动，也不需要重新部署 JAR**。
