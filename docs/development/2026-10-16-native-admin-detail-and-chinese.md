## “攻略仍是原后台”的根因

新版控制器原先仍返回 `admin-guides`，整个旧攻略模板及旧亮色、品牌修补 CSS 均被加载。接口虽然已切到 `/api/admin/xingwei/guides`，页面外壳没有完成迁移，之前测试也把旧模板当成新版 fixture。

修复使用 `admin-xingwei-guides` + `admin-xingwei-guides.css`，独立新版中文页。旧管理员回退继续渲染旧模板。共享 fragment 只负责编辑内容结构；保存、版本冲突、权限和预览继续由同一个 `admin-guides.js` 所有者处理。浏览器测试改为真实渲染新版模板、加载其实际资源，检查没有旧后台 CSS 和旧管理入口；MVC 断言实际返回独立新视图。

## 中文边界

普通员工看见的标题、导航、状态、角色、价格模式、优先级和授权范围使用中文。账号名、用户填写内容、服务/游戏名、权限码、配置环境变量名、接口值、修订号保留原义。`admin-xingwei-labels.js` 仅提供显式显示函数，无扫描替换、定时器、观察器或 DOM 补丁。运行阶段仍以原始机器值比较，避免汉化后误报版本漂移。

## 已继续推进的下一阶段

攻略运营效率和草稿保护作为本次后的第一项实质开发：

- 关键词、游戏、状态组合筛选和空结果反馈。
- q/game/status 网址保存与重新打开恢复；不修改未提交的编辑稿。
- 全选只选择实际筛选结果，切换筛选清除选择，批处理不会误带隐藏记录。
- 刷新和切换先确认放弃草稿；读取失败继续保留原稿和未保存标记。
- 读取/保存期间禁用并发切换与筛选，避免慢请求覆盖新操作。

随后优先按实际员工角色逐项走“查找 → 编辑 → 保存 → 前台结果”验收，再优化高频业务操作；支付真收款、退款、企业微信外部写入和小程序真机继续独立处理，不以完成界面迁移为由启用。

## UI 设计与验证

Visual thesis：为内容运营提供紧凑的“筛选列表 → 正文组件 → 关联服务 → 保存/预览”工作流。Signature device：游戏与发布状态直接标在攻略标题下，当前编辑项用品牌黄色边线定位。Aesthetic risk：沿用后台深色和高密度表单，舍弃旧攻略亮色兼容层。Rejected generic choice：不增加数据无关的指标卡、装饰渐变或第二套编辑器。Density / motion：均衡偏紧凑，无额外动效。Intentional tradeoff：复用编辑内容结构与业务逻辑，独立外壳和样式，降低新旧保存行为漂移。Responsive checks：桌面双栏、手机列表与编辑上下排列；检查无横向溢出。States checked：读取中、空筛选、只读、成功保存、冲突、读取失败、取消放弃草稿、预览、批量选择范围。

具体测试、CI、合并编号在验证完成后补入。本次无数据库迁移，不修改生产配置或认证权限；沿用现有权限、CSRF 和版本号检查。
