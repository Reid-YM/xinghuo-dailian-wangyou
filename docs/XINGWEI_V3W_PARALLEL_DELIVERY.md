# V3W 前后端并行交付

V3W 将两条独立开发线收进同一轮发布候选：

- 前端 PR #429：服务大厅的游戏、平台、服务类型和关键词筛选写入页面网址。分享链接、刷新页面及浏览器返回时恢复筛选；清除筛选时同步清理网址。页面仍使用原有服务数据接口。
- 后端 PR #430：客户提交订单补充说明或售后问题时，拒绝正文包含系统保留的 `[售后问题 ·` 标记。这样普通补充说明无法伪装成售后记录，售后正文也无法伪造另一个问题类型。已有订单查询权限、数据范围和审计流程不变。

两条功能 PR 已分别通过 Java/Maven 与 Chromium/WebKit CI 并合入 `main`。本统一版本更新控制台版本、Release History、首页阶段说明、业务工作台版本与相关契约和运行时测试。组合验证以本 PR 的完整 Java/Maven 和 Chromium/WebKit CI 为准；通过后再按 `main` PR、`deploy/production`、`.deploy-request` 和 18080/8081/8080 门禁发布。生产发布完成前，V3W 保持“待发布”。

没有数据库迁移或生产配置修改。历史已存储的客户说明不会自动重写；正文若确需引用系统标记，接口会拒绝提交并要求改写。V3H 小程序支付 PR #384、企业微信写入 PR #372 保持独立，真实收款不启用。
