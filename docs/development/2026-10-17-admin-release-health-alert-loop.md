# 2026-10-17 后台稳定运营：发布健康对比与告警闭环

## 目标

承接 #520、#521、#522 的运行健康与发布真值基线，继续完成 B 类稳定运营收口：

1. 让生产主机在受控发布时记录旧版 8080 与新版 8080 的只读健康探针，形成可核验的发布前后对比。
2. 将当前 JVM、数据库、近 5 分钟 5xx 与主机发布凭证组合为只读异常分级。
3. 在“版本与更新记录”页给出异常原因、来源与建议复核动作，并每 60 秒自动复核；条件恢复后自动清除告警。

## 主机发布真值

`deploy-from-github.sh` 在原有生产门禁基础上增加两个主机侧探针阶段：

- 发布前：直接访问当前正式 `127.0.0.1:8080/` 与 `/services`，记录毫秒耗时。
- 发布后：等待 8080 正式冒烟通过、Nginx 回切 8080、8081/18080 停止并完成 current.jar SHA256 一致性核验后，再次探测相同入口。

发布凭证升级为 `schemaVersion: 2`，新增 `healthComparison.preDeploy8080` 与 `healthComparison.postDeploy8080`。应用仍然只读凭证，不能自行生成发布成功结论。

为避免发布切换窗口误报，读取端继续兼容 schema v1：v1 可以证明上一轮成功发布，但不会伪造发布前后延迟；后台显示“等待下一次受控发布建立基线”。schema v2 若缺失任一健康探针则整份凭证判定为 `INVALID`。

## 稳定运营异常分级

新增只读接口：

- `GET /api/admin/xingwei/operations-alerts`
- 权限：`deploy:view`
- 缓存：`Cache-Control: no-store`

分级只使用聚合运行数据，不读取 URL、查询参数、账号、IP、订单号、请求体或异常文本。

当前阈值：

- 数据库：SELECT 1 >= 250 ms 进入观察；>= 1000 ms 警告；连通失败严重。
- JVM 堆：>= 80% 观察；>= 90% 警告；>= 97% 严重。
- 5xx：最近 5 分钟出现 1 次进入观察；>= 3 次或请求量至少 50 且错误率 >= 3% 警告；>= 10 次或请求量至少 50 且错误率 >= 10% 严重。
- 发布凭证：缺失/无效为警告；仍为 v1 时进入观察，提示下一次发布建立 v2 基线。
- 发布后延迟：最慢 8080 探针较发布前至少增加 500 ms 且达到 2 倍时进入观察。该项单独不作为生产故障或自动回滚依据。

## 告警闭环

版本页新增“稳定运营自动复核”区域：

- 综合级别：正常 / 观察 / 警告 / 严重。
- 近 5 分钟 5xx：次数、请求数、错误率。
- JVM 堆占用。
- 数据库 SELECT 1 延迟。
- 每条异常显示来源（应用运行真值 / 主机发布真值）、说明与建议复核动作。
- 每 60 秒自动刷新；条件恢复后下一次采样自动清除对应告警。
- 401/403 时失败关闭并清空已展示告警数据。

本阶段不增加“确认告警”“自动重启”“自动回滚”“自动部署”等写操作，避免诊断页面变成高风险控制面。

## 风险边界

- 无数据库 migration。
- 不修改支付、退款、企业微信写入链。
- 不新增生产配置或密钥。
- 不改变现有 Deploy Production 来源校验、main CI 门禁、18080/8081/8080 冒烟和回滚链。
- 不切换 Frontend Next 正式流量；旧版正式前端继续保持当前生产入口。
