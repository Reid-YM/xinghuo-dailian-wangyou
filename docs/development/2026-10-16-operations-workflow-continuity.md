# 下一阶段：员工运营流程连续性

基线：PR #512 新后台审查和 PR #513 前端回退已由生产发布 #219 完成。正式前端继续默认旧版；本阶段开发不改变前端切换开关，不授权再次部署。

依据细分复核计划，下一步先按员工角色检查高频的“查找 → 编辑/审核 → 保存 → 重新读取”流程。本轮集中修复会员与运营工作台六个模块共用的交互状态，不新增资金操作或外部写入。

## 已发现的问题与修复

| 问题 | 改变后的行为 |
| --- | --- |
| 关闭或 Escape 直接丢弃正在编辑的会员/CRM/审核等内容 | 输入后标记未保存；关闭、Escape、离页需要确认。成功保存或确认放弃才清除标记 |
| 模块切换或筛选失败时，上一模块记录继续显示 | 请求开始清空旧记录、计数和分页，读取失败显示重试说明，不留下可误操作的旧按钮 |
| 旧请求在新请求之后失败，把当前成功状态覆盖成错误 | 列表成功、错误和加载状态均按请求序列判断；过期结果不改当前页面 |
| 登录日志、投稿正文、展示位资料读取较慢，切换后仍弹旧详情 | 独立详情序列和列表上下文校验；切换模块、刷新、新开编辑器后旧详情失效 |
| 请求写入期间仍可能通过其他按钮发起查询或重复提交 | 保存期间拒绝重复提交、刷新、筛选和模块切换；保留原 CSRF 和 If-Match |
| 写入成功但后续读取失败，成功和失败混在一起 | 明确提示“保存成功，但列表读取失败”，清空旧列表并允许刷新，不再提示重新提交写操作 |
| 读取失败时网址仍指向上一模块 | 请求开始记录当前模块、筛选及页码，刷新网址可以重试同一个查询 |
| 编辑器关闭后仍保留密码/上传输入等表单节点 | 窗口关闭清除节点与动作，不向浏览器持久化草稿或敏感输入 |

## 角色与验收范围

| 员工能力 | 自动化检查 | 真实员工验收 |
| --- | --- | --- |
| 仅 CRM 查看权限 | 只显示客户线索、可查看详情，无维护/新增入口，不产生写请求；未知初始模块回落到已授权模块 | 待真实员工账号操作 |
| CRM 编辑权限 | 保留跟进草稿、原修改理由与版本号、请求进行中不重复写入、成功后刷新失败可重试 | 待真实员工账号操作 |
| 会员/社区/反馈/展示位管理 | 复用同一保存和关闭保护；原有全部数据范围限制仍在服务端执行 | 待真实员工账号操作 |
| ALL/DEPARTMENT/SELF | 现有服务测试继续验证线索计数/筛选、越权拒绝及全站模块限制 | 不扩大现有授权范围 |

本轮浏览器测试使用实际模板及脚本，模拟请求时序与角色能力；这不是生产真实员工登录或业务数据写入验收。相关角色和范围的服务端测试也继续执行。

## 界面与验证

不增加布局或样式层。沿用中文提示、现有列表和编辑对话框；重点验证手机下关闭/Escape、失败/重试、只读和保存状态。慢请求通过可控 Promise 延迟模拟，不使用固定等待时间掩盖顺序问题。标准 Chromium/WebKit 在 CI 执行；本地使用可用的 Edge Chromium。

变更所有者：`admin-xingwei-operations.js` 处理状态及请求；`admin-xingwei-operations.html` 更新脚本缓存版本；`XingweiOperationsPlaywrightTest` 验证连续性与只读角色；本文件记录范围和验收边界。无数据库迁移、认证协议、权限规则或生产配置修改。
