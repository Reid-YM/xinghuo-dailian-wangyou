# 目录完整资料与业务维护迁移

原生入口新增 `/admin/xingwei/catalog-details` 和 `/admin/xingwei/maintenance`，从目录、游戏分类和业务工作台直接进入；不依赖旧 `/admin` 或旧 API。

## 补齐的原有能力

- 服务：封面上传及 URL、归属游戏/分类、slug、价格、热度、人工优先级、有效期、AVAILABLE/BUSY 状态。
- 游戏：英文名/别名、发行方/类型、Logo/封面、热度/重点标记、业务状态、SEO、支持平台；批量资料维护及逐项影响预览后的批量启停。
- 无依赖游戏/分类的永久删除：恢复 ADMIN、准确编号、当前版本及原有依赖检查。
- 业务：按权限和 ALL/DEPARTMENT/SELF 范围查询订单/询价，公开案例设置需客户授权确认与脱敏摘要；永久删除仅恢复 ADMIN、准确业务号和当前版本，并复用原有支付/依赖阻断。

完整目录写入要求 service:manage + ALL；只读账号没有保存、上传或批量入口。图片上传先审计申请，返回真实受控素材 URL，再保存引用，不把上传等同于资料已生效。

## 修复保存覆盖与启用绕过

服务使用现有 JPA version；游戏、分类和业务维护使用现有 updated_at 摘要作为 If-Match，锁行后执行原服务，事务 flush 后返回新版本。简版/完整编辑共用版本，不用两个互不相识的修改时间。

简版服务仅负责文案、价格和排序，保存时从锁定的当前记录保留封面、有效期、归属和启用状态；忽略客户端伪造的这些字段。新增服务强制 OFFLINE + false；完整资料保存也保留当前启用开关；在线服务的资料变更重新经过发布检查。游戏和分类启停在同一锁下重新校验影响 token，避免与完整资料写入互相覆盖。写事务显式 READ_COMMITTED，锁后读取当前字段，避免 MySQL REPEATABLE_READ 下权限查询提前建立的旧快照再次覆盖新字段；读取快照继续使用同一只读事务配对字段与版本。批量按规范化编号排序锁定。

简版 taxonomy 编辑先读取匹配的当前字段和版本，不能拿新版本给旧字段背书。简版脚本更新资源版本，页面 no-store。HTTP 409 保留当前输入，不自动刷新、重试或假报成功。

批量启停与资料批量分开；读取影响时冻结弹窗，完成后勾选确认才可保存。表单先取得 FormData 再禁用控件，避免发出空保存。有效期按浏览器本地时间编辑，提交 UTC。

## 验证与边界

- H2 事务测试：共用版本、旧版本拒绝、发布失败回滚、资料保存保留开关、批量预条件、范围先于计数分页、公开授权、审计失败回滚、准确删除编号及原支付依赖保护。
- 真实 SecurityConfig 与 MVC：匿名、缺少模块权限、CSRF、部门账号写全局目录和非 ADMIN 永久删除均拒绝，拒绝发生在业务读取/写入之前。
- 实际 Thymeleaf + 脚本的 Chromium/WebKit 测试：封面上传再保存、UTC/上海时间、平台与 SEO、影响确认、冲突输入保留、公开授权、删除支付阻断、只读账号、手机视口；简版字段与版本配对及请求 If-Match。
- 所有浏览器写入均为 fixture，不操作生产数据，不调用实际支付或企业微信写入。

无新增数据库 migration、无开关或生产配置修改。开发集成后仍须统一版本与完整 CI、主线及发布核验。
