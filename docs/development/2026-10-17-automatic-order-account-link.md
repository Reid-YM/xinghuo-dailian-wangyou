# 2026-10-17 订单客户账号自动关联

## 背景

微信 Native 支付工作台已经可以读取订单并录入最终报价，但历史订单或人工链路中可能出现 `customer_orders.customer_account_id` 为空的情况。此前页面会提示去业务工作台手工关联，但后台实际上没有对应的人工绑定入口，导致报价与支付闭环被卡住。

## 本次目标

把客户账号归属改为自动获取、自动关联，同时保持身份边界：系统只使用可信来源，不根据未验证的辅助联系方式或模糊文本猜测客户身份。

## 自动关联规则

按优先级执行：

1. **统一业务编号对应的询价已经有 `customer_account_id`**：直接继承该账号归属。
2. **询价尚无账号归属，但主联系方式可以唯一匹配到 ACTIVE 且 `contact_verified=true` 的网站账号**：按统一联系方式规范化后自动关联。
3. 已有订单归属绝不覆盖。
4. `quote_contacts` 等免验证客服回访联系方式不作为身份依据。
5. 无法通过以上可信信号确认时保持未关联，不做危险猜测。

## 触发点

- 后台「订单报价与微信收款」读取订单时自动核对并修复归属；修复后页面立即显示订单具备支付资格。
- 用户打开「我的订单」时自动修复属于该账号的历史订单，并记录 `ORDER_AUTO_LINK` 账号审计。
- 支付工作台自动修复会记录 `XW_ORDER_ACCOUNT_AUTO_LINK` 管理审计。
- 旧的人工认领接口继续保留为历史数据异常时的安全兜底。

## 安全边界

- 不自动覆盖已有 `customer_account_id`。
- 不使用未验证主联系方式匹配账号。
- 不使用辅助询价联系方式作为身份依据。
- 支付工作台仍先执行 `payment:view` / `payment:manage` 与业务数据范围校验，再执行自动归属。
- 不改变微信支付金额确认、签名验签、到账 `CAPTURED` 判定逻辑。
- 不修改 Frontend Next 正式切换状态。

## 验收

1. 询价已绑定账号、订单未绑定：读取支付订单后应自动补齐。
2. 询价未绑定账号，但手机号/QQ/邮箱等主联系方式与一个已验证 ACTIVE 账号唯一匹配：应自动补齐。
3. 联系方式未验证或账号非 ACTIVE：不得自动补齐。
4. 订单已有其他账号归属：不得覆盖。
5. 自动补齐后，支付工作台应直接显示最终报价表单，可继续 0.01 元 Native 支付验收。
