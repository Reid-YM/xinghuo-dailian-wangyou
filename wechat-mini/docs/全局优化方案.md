# 星火迷彩小程序全局优化方案

更新时间：2026-10-12。范围：当前 5 个页面、数据与云同步、图片、内容、开发验证和发布资料。本方案以现有项目为基线，不把视觉相似度当作官方授权或官方产品身份。

执行状态：小程序源码、云函数、模拟器视觉、预览和远端攻略源内容已完成本轮优化，详见 [执行记录](./执行记录-2026-10-12.md)。两台真机测试和体验版/正式发布仍按 [上线清单](./上线清单.md) 执行。

## 一、当前基线

| 方面 | 已确认的现状 | 影响 |
| --- | --- | --- |
| 页面 | 首页、攻略列表、攻略详情、查单、我的共 5 页；没有需要删除的整页 | 保留四个 Tab 和攻略详情页，优化页面内部层级 |
| 功能 | 静态校验、逻辑模拟、云同步回归、图片文件映射检查通过 | 可在此基础上迭代，不重写核心逻辑 |
| 首页 | 总进度、模式选择、客服、解锁要求、三档迷彩、筛选、武器列表、分享和查单都在同一页 | 首屏重点不够集中，长列表难以快速定位 |
| 我的 | 已按账户、概览、数据管理、帮助、关于分组 | 还需用真实设备验证登录前后、长昵称、小屏幕和大字体排版 |
| 攻略 | 线上 11 篇中 1 篇整篇未收录，14 段内容被运行时过滤 | 内容应在源头整理；自动过滤不能代替人工内容审核 |
| 图片 | 本地映射检查 16 个引用正常；实际项目有 32 个图片文件 | 仍需真机确认包内图、网络封面及加载失败状态 |
| 发布资料 | README 和上线清单含 Windows 路径、旧同步描述与若干过时步骤 | 容易误导后续部署与验收 |

## 二、目标与设计原则

1. **专业、可信、克制**：沿用深色游戏工具基调，用统一的字号、留白、边框、状态色和按钮等级；不使用“官方出品”等无法证明的身份表述。
2. **一屏一个主要任务**：首页优先展示进度与继续记录；攻略用于阅读；查单用于查询；“我的”用于账户和数据管理。客服入口保留，但不压过当前任务。
3. **状态真实可理解**：明确区分本机保存、云端同步中、同步成功、同步失败和离线快照。任何“已保存”文案都应与实际状态一致。
4. **操作可恢复**：清空、退出、导入等操作有明确结果和确认；登录、网络请求和图片失败时仍能继续使用基本功能。
5. **先验证后发布**：命令行编译成功只证明能预览，视觉、图片、账户和网络流程仍需模拟器与真机验收。

## 三、设计优化

### P0：首页信息架构

- 首屏顺序固定为“总进度 → 模式选择 → 当前模式进度”，将客服卡移到首个武器组之后或页面底部的帮助区，避免打断记录流程。
- 将“解锁要求”与“三档迷彩”合为一个当前模式模块：三档摘要常显，详细要求按需展开，减少相邻卡片的重复说明。
- 筛选区保留搜索、职业和状态三类控件；显示当前筛选结果数，并提供一键清除筛选。无结果时给可操作的空状态。
- 武器行统一“名称 → 当前进度 → 三档状态”的阅读顺序；收藏、展开、勾选的点击目标按真机测量，避免误触。
- Event 单独标识，并明确它与普通武器三档进度的统计关系。

**验收**：不滚动即可看到总进度和当前模式；搜索、切模式、勾选与展开在小屏幕上不互相挤压；切换筛选后能看见结果数和恢复入口。

### P1：“我的”与跨页视觉规范

- 建立一套设计变量：背景、表面、边框、主色、正文/次级文字、成功/警告/错误色；统一标题、说明、卡片、列表行和按钮尺寸。
- “我的”继续采用资料卡 + 设置列表：同步状态放在账户附近；清空进度与普通操作视觉分开；关于信息采用名称/值对齐。
- 为未登录、登录中、已登录、同步失败、空进度分别检查文案与布局；昵称过长时截断并保留可编辑入口。
- 攻略列表统一封面比例、标题最多行数和元数据间距；详情页建立标题、正文、列表、FAQ 的文字层级。
- 查单页将输入、查询结果、错误提示和历史记录分层；业务状态用文字加颜色表示，不能只靠颜色。
- 所有页面统一加载、空、失败、离线状态的版式和措辞。

**验收**：在常见窄屏和系统大字体下无文字截断、重叠或横向滚动；同类组件在所有页面看起来一致；主要按钮与危险操作一眼可区分。

## 四、工程优化

### P0：发布前正确性

1. **云同步版本对齐**：当前客户端使用支持增删的新版同步协议，线上 `syncProgress` 是否已更新需以云端版本或实际跨设备测试确认；发布前完成“设备 A 取消 → 设备 B 恢复”“清空后重登”“并发修改”测试。部署是独立的生产操作。
2. **真机图片与域名验证**：分别在合法域名已配置和断网条件下检查包内迷彩图、武器图及网络攻略封面；不要用 CLI 报出的代码包大小推断图片是否包含。
3. **数据一致性**：服务端数据版本、离线快照版本和页面总数应在同一份验收记录中核对；若官网新增武器或迷彩，确认旧进度键仍有效。
4. **账号与数据操作**：覆盖首次登录、重复登录、退出、重新登录、头像上传失败、分享码导入去重和清空确认。失败提示不得声称同步成功。

**验收**：上述场景有可复现记录，跨设备结果一致，云端失败时本机记录可继续使用。

### P1：可维护性与性能

- 将品牌、版本、数据源和状态文案集中管理，消除 `app.js` 与“我的”页等位置的手工版本号；增加构建前版本一致性检查。
- 首页减少大对象的全量 `setData`：只更新受勾选、模式或筛选影响的字段；在真机性能面板确认长列表滚动、搜索输入和勾选没有明显卡顿后再决定是否分组分页。
- 给接口数据做结构校验与错误分类：超时、非法响应、业务错误分别处理；缓存回退时明确显示数据时间或来源。
- 给关键异步流程建立统一约定：页面卸载后不再写入页面状态；重复点击时禁用提交；重试不会覆盖更新结果。
- 清理不用的样式、旧注释和重复文案；持续保持当前 `validate`、`simulate`、`test-sync` 测试通过。

**验收**：同一版本只改一处；异步异常不造成白屏或错误成功提示；搜索和勾选操作流畅。

### P1：内容与文档

- 把当前被过滤的攻略内容交由内容源头修改，再检查列表、正文、FAQ 和相关攻略；当前脚本报告 1 篇未收录、14 段过滤、23 处需人工确认，不能把脚本通过视为审核或合规保证。
- 更新 README 与上线清单：改成当前 macOS 项目路径或跨平台命令；说明新版同步协议和云函数部署状态；修正旧包体积、图片、数据库和域名说明；修复损坏的 Markdown 代码块。
- 建立发布记录：源码版本、云函数版本、数据快照日期、预览二维码、真机截图和测试结果放在同一处。

**验收**：新开发者只按文档即可完成本地预览；发布记录可追溯客户端与云函数的对应版本。

## 五、执行顺序

| 阶段 | 优先级 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| 1. 视觉基线 | P0 | 首页、我的、攻略、查单的正常/空/错误截图 | 真机审阅并固定布局问题清单 |
| 2. 首页与组件 | P0 | 首页信息架构、统一状态组件 | 首屏清晰，重复模块减少，交互测试通过 |
| 3. 数据与同步 | P0 | 客户端/云函数版本核对、跨设备验证记录 | 删除和清空可跨设备正确同步 |
| 4. 内容与说明 | P1 | 清理后的攻略、更新后的 README/上线清单 | 内容抽检和文档操作验证通过 |
| 5. 发布验收 | P0 | 预览包、真机截图、验收记录 | 页面、图片、网络、客服和账户流程逐项通过 |

建议先做阶段 1–3，再进入发布验收。功能迭代和生产部署分别记录，避免本地通过测试后误以为线上已更新。
