# 2026-10-17 新版后台运行健康可视化

## 目标

承接 PR #520 已上线的只读运行健康 API，把应用进程能够自行证明的健康真值放进新版后台现有“版本与交付”专页，作为稳定运营阶段的日常核验入口。

## 本次行为

- “版本与更新记录”页新增“运行健康”区域。
- 读取 `/api/admin/xingwei/runtime-health`，继续由 `deploy:view` 权限保护。
- 展示数据库 `SELECT 1` 连通状态与耗时、JVM 运行时长、堆内存、线程数、当前 JVM 启动后的总请求、4xx、5xx、最近一次 5xx 与采样时间。
- 5xx 历史存在时显示警告，但不直接把历史 5xx 等同于当前故障；数据库连通失败才显示明确异常。
- 支持手动复核、页面重新可见时复核、浏览器恢复联网时复核，以及页面可见期间每 60 秒自动复核。
- 403 时保持失败关闭，只提示当前账号缺少 `deploy:view`，不展示伪造或缓存的运行数据。
- 成功读取后若后续单次请求失败，保留上一次成功快照并明确标记“复核失败”，不把旧数据伪装成实时数据。

## 真值边界

本页只展示应用进程内真值，不读取或声称以下主机/发布状态：

- Nginx 当前 upstream；
- systemd 服务状态；
- `current.jar` / `current-release.env`；
- Git SHA；
- JAR SHA256；
- 上一版本 release 与真实回滚链；
- 18080 / 8081 / 8080 发布门禁结果。

这些内容继续只以 `Deploy Production` 生产流水线和生产主机核验为准。页面不会执行部署、回滚或任何业务写入。

## 隐私与数据面

运行健康仍只使用 PR #520 的聚合指标。前端不请求或展示 URL、查询参数、请求体、账号、IP、订单号、业务编号或数据库异常文本。

- Chromium 回归覆盖正常指标、历史 5xx 警告、手动复核恢复正常和 `deploy:view` 403。
- 完整 Java/Maven 与 Chromium/WebKit 全量回归由 PR CI 验证。

## 发布

无数据库 migration、无生产配置变更、无支付/退款/企业微信写入。CI 全绿并合入 main 后，按既有受控流程执行生产发布与 18080 → 8081 → 8080 核验。
