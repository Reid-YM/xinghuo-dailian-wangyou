# 站点、SEO 与前台控制的新版入口

状态：开发验证中，整体后台完成后统一部署。

## 完整操作路径

- `/admin/xingwei/site`：品牌/业务开关、首页/价格、视觉图片、公告、客服渠道、案例/FAQ、业务文案、SEO、工具站公开设置与真实游戏服务状态。
- `/admin/xingwei/frontend-controls`：复用现有完整导航、备案、首页展示与主题编辑界面，但仅请求新版受控 API。旧 `/admin/frontend-controls` 默认模式和 API 保留。
- 配置页采用中文字段与可增删列表，不要求运营人员编辑 JSON。图片可先上传为草稿，保存当前分区后才影响前台，支持地址预览与加载失败提示。

## 权限与一致性

读取执行 site:view/seo:view；全局写入同时要求对应 site:manage/seo:manage 与 ALL 范围。普通查看者只能读取；SEO 管理与站点管理分离。没有修改既有角色、权限表、认证或旧后台的外层门槛。

GET 返回 ETag，保存要求 If-Match；新入口写入借现有单例行锁串行化，过期配置返回409并保留输入。只合并当前分区字段，省略字段从当前数据补齐，防止意外清空。新旧入口仍共用 SiteConfigService、SiteSettingService、FrontendControlService 与 GameStatusService；没有第二份配置源。

游戏状态有独立编辑区，调用实际 GameStatusService，不以修改 site_config 的历史兜底字段冒充前台状态已变化。新增兼容重载传递本次修改原因，旧方法保留原默认原因。

所有配置写入与审计在同一事务；图片上传复用既有文件类型/大小校验，不自动改变配置。新入口拒绝可执行地址、协议相对地址与带口令的 URL。无数据库迁移、生产配置或外部平台写入。

## 验证

- H2 + 真实配置服务验证：新版保存写入后，现有公开配置读取能得到同一值；审计失败和后续字段校验失败均完整回滚。
- 服务测试覆盖全局范围、SEO分权、ETag冲突、字段保留、跨分区字段拒绝、不安全地址拒绝、图片草稿与真实游戏状态调用。
- Thymeleaf 实际渲染新旧模式，检查新入口返回链接、旧默认行为和CSRF元信息。
- HTTP 层验证 ETag/If-Match 与 no-store。
- Chromium/WebKit 实际模板覆盖保存、CSRF、版本冲突、草稿图片、只读控制与390px布局；浏览器验证由 Linux CI 执行。

## UI

主任务是选择区域后修改和保存，紧凑配置分区与双列表单；手机单列，图片可预览，案例/客服用可增删字段行，避免巨大 Hero 和内部 JSON 编辑器。保存期间冻结表单，失败保留草稿，离开或切换分区时提示未保存内容。
