# 工具站资料和行为统计迁移（待统一发布）

旧菜单核对补录 MW4 资料编辑和行为统计，新增 `/admin/xingwei/tool-station`、`/admin/xingwei/statistics`。工具编辑器复用原有模板片段和脚本所有者，正式新版不再加载旧主菜单注入脚本。

工具站读取/维护沿用 content:view/manage，并要求全部数据范围。写入和恢复要求精确 If-Match 与修改说明；读取、旧/新写入共用进程内路径锁及文件锁，采用临时文件原子替换并保留上一版 .bak。请求审计先于文件操作，审计不可用时不写文件；文件写入失败返回失败，审计里的 requested 字段只表示修改请求。图片上传沿用现有服务，不直接发布文件路径。

修复原编辑器连续保存时 weapon 仍引用旧 config 的问题：保存后重新绑定服务端返回的当前武器，再次修改会进入实际发送数据。冲突保留表单，刷新或切换武器前提示放弃未保存修改。只读用户只能选武器查看。

统计沿用真实 tracking_events 聚合，不把事件次数说成独立用户或同一批用户的转化率。全站统计要求 dashboard:view 和 ALL 范围；服务、新询价、进行中/已完成订单、新反馈等旧概览指标分别在对应模块权限通过后才查询，避免全局统计泄露其他模块数据。

正式新版前台补齐已有事件类型，提交成功后才记录 quote_submit，来源/UTM 在站内路由及刷新后保留。统计请求只含事件名、公开页面路径及业务引用，不发送客户联系号、需求正文或截图内容。原英文切换入口原本已下线，本轮保持原决定。

验证包含跨实例文件版本互斥、审计失败不写文件、备份与原子替换、全站范围与只读、模块计数先授权再查询；真实模板片段渲染的浏览器用例覆盖连续两次保存、If-Match/CSRF、冲突保留、只读、手机布局和统计安全文本。已使用本机 Edge 的 Chromium 引擎验证连续编辑实际请求体，Linux CI 继续验证标准 Chromium 与 WebKit。来源与事件回归覆盖实际新版全运行时、站内导航、刷新、询价成功与联系号不进入统计。
