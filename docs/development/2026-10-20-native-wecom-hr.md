# 新版企业微信员工和部门管理

## 功能与边界

原生 `/admin/xingwei/wecom` 增加新增员工、调整岗位、停用员工、新增部门和部门改名，使用 `/api/admin/xingwei/wecom/hr`，不恢复旧后台页面、脚本或 API。岗位取 V63 正式目录，仅允许启用岗位和启用中心；选中的企业微信部门名称必须与岗位中心一致。部门改名不自动改写 V63 岗位中心目录，不删除部门或成员。

原只读客户端继续只用应用读取凭据；新写客户端独立使用服务端 `WECOM_SECRET` 和独立 token，配置入口 `wecom.write-secret`。`WECOM_HR_WRITE_ENABLED=false` 为默认值，不随已有凭据自动开启。能力状态不代表企业微信授权或真实验收已经成功；集成页分别显示凭据准备、写入开关和专门成员验收。

只有拥有 `employee:manage` 且数据范围为 ALL 的账号可执行；仅有部门 / 本人范围的账号不能通过伪造请求越权。原 SecurityConfig、CSRF、后台会话版本继续执行。用户只看到业务名称，成员标识、岗位代码和确认凭证只用于隐藏协议；联系人不写入审计或错误日志。

## 执行协议

1. 服务端从有限操作生成预览，拒绝任意厂商 payload。新增成员标识由服务端生成，联系人仅用于该成员创建。
2. 预览只保存于当前后台会话，有效期五分钟；重新预览撤销旧预览。返回业务摘要和隐藏的一次性确认凭证。
3. 输入预览中的名称确认。提交核对当前操作者、权限、会话、有效期和名称；确认凭证在写入前消费，不自动重试。
4. 写入前重读并比较成员 / 部门状态，重新校验岗位目录。厂商 API 没有本应用可用的条件更新协议；这能拒绝已观察到的过期数据，不能承诺与厂商后台并发编辑的原子 CAS。
5. 调岗明确用选定部门替换原部门归属。停用本人或已绑定的系统管理员会拒绝；其他已绑定账号先持久停用本地登录、增加会话版本并标记员工 INACTIVE，再向企业微信提交。厂商结果不明时本地访问保持停用，不自动恢复。
6. 厂商成功响应后仍回读具体成员 / 创建部门 ID，确认实际状态。超时、错误、回读不符均显示待核实并禁止当前表单再次提交。审计记录请求与已确认 / 待核实结果，不记录联系人、token、请求 URL 或厂商诊断。

企业微信新登录每次核对成员当前状态，仅已激活且未停用的成员可建立登录身份；核对失败不再仅凭 OAuth 身份登记 / 登录。原有手工角色不因新增状态核对而重跑自动角色同步。此安全约束意味着通讯录读取不可用时登录会拒绝，须完成专门员工登录验收。

## 隔离验证

新增真实 SecurityConfig MVC 验证权限、全企业范围、CSRF、会话隔离、名称确认、一次性消费，以及先撤销本地访问再发外部请求；真实 H2 状态检查覆盖登录开关、会话版本、档案状态、绑定及历史备注保留。聚合服务测试覆盖岗位中心、不存在 / 变化的数据、成员停用与厂商回读。环回 HTTP 服务检查独立写 token、缓存、请求方法、错误去敏及不自动重试。成员解析和 SSO 回调测试覆盖停用 / 离职 / 未激活拒绝及既有角色同步条件。

Chromium 与 WebKit 本机交互通过：新增员工的预览 / 名称确认、再次打开表单、调岗、部门改名、停用待核实、权限失效隐藏管理按钮。最终完整 Maven clean package 共 995 项、0 失败、0 错误，227 项 UI 交独立浏览器任务；406 项搜索索引和发布状态一致性检查通过。正式 PR / 主线 CI 和发布结果仍须单独核验。

## 尚需真实验收

本批没有调整生产开关、执行真实企业微信成员 / 部门写入或新增数据库迁移。代码发布和写入启用分别验收；启用前需要明确许可和专门的测试员工 / 部门。真实创建、调岗、停用及旧会话撤销、已停用成员重新登录拒绝均需按指定对象逐步核对。真实退款、游客转账号、历史归属治理等完整后端待办继续保留。
