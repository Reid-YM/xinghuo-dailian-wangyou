# 后台默认入口完全替换（待统一发布）

`/admin` 现在默认重定向到新版 `/admin/xingwei`；`/admin/guides` 默认重定向新版攻略工作台。原 ADMIN 可显式用 `?legacy=1` 进入恢复模板，页面不缓存，新版链接改为明确的恢复链接。

完整迁移后，普通员工只使用 `/api/admin/xingwei/**` 和对应的权限/数据范围。历史 `/api/admin/**` 仅向原 ADMIN 开放，避免员工从旧接口绕过新版角色及业务归属控制；网站会员自建会话路径及公开 API 不变。新接口仍要求后台登录、具体模块权限和写入 CSRF。原 ADMIN 保留恢复能力，不删除旧数据和模板。

企业微信会话允许默认入口跳转新版，但继续禁止进入旧恢复模板和历史 API。没有扩大企微会话的范围。

验证包含实际 SecurityConfig + Spring MVC HTTP 测试：ADMIN/OPERATOR 默认跳转、原 ADMIN 恢复、员工恢复拒绝、历史读写拒绝、新模块方法权限、CSRF、匿名401，以及有效企微会话的默认入口与恢复拒绝。开发期不部署，最后集中发布。

## 支付操作迁移

新增 `/admin/xingwei/payments`，全程使用原生星维接口。列表先按业务归属过滤再计数分页，不返回 Native code_url；原集成配置页只有 ALL 范围能读取全站支付汇总，窄范围通过原生工作台查看自己的记录。

建单要求 payment:manage、可见订单、订单版本和客服确认金额/服务/说明，复用现有 Native 服务的绑定与重复建单检查。关闭要求对应支付单的业务范围、版本和权限，并在调用服务前写入“请求关闭”审计；若服务端确认已到账，界面明确显示到账且未关闭。开关未开启时仅提供读取，页面不自动建单、收款或查商户。

本地 SQL/事务测试与浏览器 fixture 验证权限、范围、CAS、开关、CSRF、金额请求体、失败保留输入及服务端到账结果；没有调用实际商户服务。后台工具站资料编辑、行为统计两项在旧菜单核对时补录，继续开发，不把默认入口切换等同于全部功能已齐。
