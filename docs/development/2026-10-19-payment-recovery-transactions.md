# 定时支付恢复的逐笔事务边界

`recoverPending` 通过同一服务实例调用 `close`，不会经过 Spring 事务代理。虽然 `close` 标注了 `@Transactional`，该定时路径仍可能在自动提交下执行 FOR UPDATE，无法保持行锁；发现延迟到账时，如果状态更新成功而流水写入失败，还可能留下部分写入。

过期关闭改为使用现有 TransactionTemplate 显式开启逐笔事务。关闭中的行锁、到账状态和收款流水处于同一事务；异常回滚该笔并由原有逐笔异常处理继续后续记录。不对整个批次开启长事务，主动查单的外部请求和原有到账事务保留。

新增隔离 H2/模拟 SDK 测试：

- 过期关闭请求期间确有活动事务，结束后事务释放。
- 第一次查单未支付、关闭前查单发现到账，但插入流水唯一键冲突时，支付状态和交易号一起回滚。
- 一笔关闭失败后，下一笔过期支付仍可正常关闭。

无 migration、生产配置、权限或认证变更；没有真实商户请求或生产业务写入。回滚代码会重新暴露定时路径缺少事务的问题。本批属于后续开发，生产发布仍需独立核验。
