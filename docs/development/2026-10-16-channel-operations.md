# 新版后台渠道运营工作台

状态：开发验证中，纳入后台整体完成后的统一发布；本阶段不发布生产。

## 解决的问题

后台 C01 原为占位入口。新增官网、淘宝、闲鱼的内部服务状态与运营任务，让运营人员能够按负责人、中心、渠道和处理状态安排工作。这里是人工维护的协作记录，不代表平台接口实时状态，不自动发布商品，也不更改前台接单、订单或付款状态。

## 交付

- `/admin/xingwei/channels`：独立工作台，加载失败可重试。
- `/api/admin/xingwei/channels`：服务状态、范围内任务、负责人候选、权限标记和分页。
- 任务新增、编辑、负责人、截止日期、说明及待处理/进行中/已完成/已取消；取消保留记录，不提供物理删除。
- 筛选和页码写入 URL，支持刷新和前进/后退。
- 所有读写执行 `channel:view / channel:manage`；ALL、DEPARTMENT、SELF 与无中心回退规则服务端强制执行，兼容操作员只读。
- 统一服务状态只允许拥有 `channel:manage` 且 ALL 范围者维护。
- 写入版本冲突返回 409；审计与业务在同一事务，审计失败不保留未审计变更；前端保留失败时的输入。
- 使用安全 DOM 文本插入、CSRF、保存防重复点击、超时提示；保存成功但列表刷新失败会明确区分。

## 数据库与回退

V75 只新增 `xw_channel_status` 与 `xw_channel_tasks` 两张表，三渠道默认 UNKNOWN。既有表和迁移均不修改，不新增外部平台凭据，不写支付或企业微信。已逐行评审 DDL，精确 Git blob SHA 登记在 REVIEWED_FLYWAY_MIGRATIONS，并由契约测试锁定。

旧 JAR 可继续使用原有业务表，回退不需要删除新增表。JAR 回退不会回滚新增表或运营记录。

## Visual thesis

- 业务主任务：先看渠道是否可接服务，再筛选和跟进运营任务。
- 密度与布局：紧凑的三渠道状态栏与连续任务列表；宽屏任务双列，手机单列，编辑在可聚焦对话框中完成。
- 视觉签名：每项任务固定显示渠道、负责人、中心、截止日期与处理状态，文本说明可展开。
- 取舍：复用现有星维颜色和按钮，拒绝巨大 Hero、装饰性图表和虚构经营指标。
- 必查状态：只读/可管理、空、加载失败重试、版本冲突、保存、表单校验、长标题、手机和桌面。

## 验证

- H2 直接执行 V75，服务测试覆盖 ALL/DEPARTMENT/SELF/无中心、越权、停用负责人、只读账号、乐观锁、审计回滚、搜索和分页。
