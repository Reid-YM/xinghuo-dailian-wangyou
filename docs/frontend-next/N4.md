# Frontend Next N4：账号 / 微信登录 / 个人中心真实数据

## 目标

继续保持旧前端在线，在 `/next/account` 接入现有生产账号能力，不复制账号表、不新建第二套会话体系。

## 本阶段接入

- `GET /api/account/me`：读取当前登录账号档案。
- `POST /api/account/login`：新版个人中心内直接账号登录。
- `POST /api/account/logout`：退出当前账号会话。
- `GET /api/account/orders`：读取当前账号已归属订单。
- `GET /api/account/sessions`：读取当前账号登录设备。
- `GET /api/account/security/events`：读取最近账号安全活动。
- `GET /api/account/wechat/availability`：判断微信开放平台网站扫码登录是否已配置。
- `/api/account/wechat/start?next=/next/account`：配置可用时启动现有微信 OAuth 扫码登录，成功后回到新版个人中心。

## 数据原则

- 个人中心只渲染服务端返回的当前账号数据。
- 不在新版页面伪造订单金额、时间线节点或进度。
- 订单统计中，总数使用服务端 `total`；进行中 / 已完成明确标记为“本页统计”。
- 未归属历史订单继续使用旧版账号中心的认领能力，本阶段不复制该写操作。
- 设备 IP 使用服务端已有脱敏值。

## 安全与回退

- `/next/account` 页面本身仍是公开壳层；账号数据继续由现有 `@RequireAccount` 保护。
- 所有账号请求使用 same-origin cookie；写请求带 `X-Requested-With: fetch`。
- 微信 OAuth 只调用现有 start / availability 端点；前端不包含 AppSecret、access token、openid 等敏感信息。
- DOM 动态内容使用 `textContent` / `replaceChildren` 等 API，不使用 `innerHTML`。
- 旧 `/account`、`/account/login`、`/account/register`、`/account/reset` 不修改，作为完整功能与回退入口继续保留。
