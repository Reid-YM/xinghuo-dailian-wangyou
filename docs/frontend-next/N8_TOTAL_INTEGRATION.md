# Frontend Next N8：替换前总联调与稳定化

> 以下记录原阶段设计；当前默认入口和完整替换以 [完整迁移计划](../development/2026-10-16-complete-migration-plan.md) 为准。

日期：2026-10-15

状态：独立并行联调阶段，不切旧前端默认入口。

## 目标

N1–N7 已分别完成视觉、服务、询价、账号、业务闭环、安全设置与统一认证。N8 不再扩张业务模型，而是把“是否具备逐页替换旧前端的资格”变成可重复验证的门禁。

## 本阶段改动

- 新增 `/next/n8-integration.js`，必须在 N2–N7 全部 runtime 之后加载。
- 清理首页仍残留的早期 V1 演示语义：
  - 示例进度卡明确说明只用于界面展示，不代表当前账号真实订单。
  - 首页状态文案明确说明服务大厅、真实询价、账号、业务记录和安全设置已经逐步接入现有接口。
  - 明确 `/next` 仍是并行入口，旧前端继续保留回退。
- 新增离线提示：网络断开时只提醒用户保留当前输入并等待恢复，不自动提交、不改业务数据；恢复网络后自动清除提示。
- 新增 `prefers-reduced-motion: reduce` 支持：关闭页面入场、悬浮位移和主要过渡，并把平滑滚动切回即时滚动。
- runtime 仅把 N2–N7 可见模块数量写入页面 dataset 供诊断；它不会因某个可选模块缺失而阻塞用户。

## 替换前硬门禁

1. Controller 注入顺序必须保持：N2 → N3 → N4 → N4 Mini → N5 → N5 Actions → N6 → N7 → N8。
2. `/next`、`/next/services`、`/next/quote`、`/next/account` 继续独立运行。
3. 旧 `/account`、`/account/login`、`/account/register`、`/account/reset` 必须继续存在。
4. `/admin/**`、`/api/admin/**` 继续要求 ADMIN / OPERATOR，Frontend Next 不加载后台 runtime。
5. 服务、询价、账号、业务中心、安全设置和统一认证继续复用现有 API，不建立第二套数据库模型。
6. 前端失败必须可降级或重试，不得把展示失败误报成业务写入失败。
7. 手机端离线提示不能超出视口；系统要求减少动态效果时必须停用非必要动画。
8. V3H 小程序真实支付继续保持独立真机验收边界；N8 不借总联调提前合并真实支付分支。
