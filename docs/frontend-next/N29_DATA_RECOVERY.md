# N29 第二阶段 · 数据读取状态与失败重试收口

## 本轮真实缺口

1. **信任中心公开完成案例**：原 N27 在 `GET /api/public/cases` 超时、HTTP 非 2xx 或返回异常结构时，把数据设置为空数组，最终显示“当前没有公开完成案例”。用户无法判断是没有案例还是网络失败，且不能原位重试。
2. **投稿工作台的游戏选择**：原 N25 在 `GET /api/catalog` 请求失败时，只给短提示，无法在原编辑器重试，用户可能因游戏选择不可用而阻塞投稿。

## 修复

- N27 公开案例提供 `idle/loading/ready/error` 状态，明确区分“读取失败”和“确实没有公开案例”；失败时提供“重新读取公开案例”，使用同一个公开 GET 接口；不显示模拟数据，不增加写接口。
- 错误状态不会自动重复请求，避免失败后无限轮询；重试时先展示加载态，成功后才展示真实公开数据或空状态。
- 请求 token 防止旧响应覆盖新结果；案例容器添加 `aria-live=polite`，让辅助技术能感知读取状态变化。
- N25 在游戏选择控件下增加有语义的错误提示和“重新读取游戏列表”按钮，重试成功只更新游戏 options，保留已填写的标题、摘要、正文及本机草稿。
- 不更改 `/api/catalog`、`/api/public/cases`、服务端鉴权、正式 Legacy、订单、支付、部署默认前端或站点内容来源。

## 验收

- `FrontendNextN29PublicCasesRecoveryTest`：合同及 Chromium 503 → 重试 200 空数组，验证失败不伪装为空、重试次数和真实空状态。
- `FrontendNextN29SubmissionCatalogRecoveryTest`：合同及 Chromium 503 → 重试 200 游戏列表，验证编辑器内容未被重置。
- 与 N23–N29 整栈组合运行 Maven 和 Chromium+WebKit。
- 本次属于 N29 的第二阶段，不等于全部页面的错误态与全链路验收已完成。
