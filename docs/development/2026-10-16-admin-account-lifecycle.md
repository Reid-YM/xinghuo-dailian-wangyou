# 后台员工账号生命周期（待统一发布）

账号与登录安全页直接管理后台登录账号，复用 admin_users、BCrypt、Spring Security 和星维 RBAC，不创建另一套密码系统。网站会员仍由独立的会员权限管理。

读取要求 employee:view 与全部数据范围；维护要求 employee:manage 与全部数据范围，创建还要求 rbac:manage。创建员工时事务内先建立停用账号、有效档案和明确启用的星维角色，再启用登录；失败整体回滚，避免未分配角色落入兼容模式。ADMIN 创建及维护只允许现有恢复 ADMIN。角色/状态及改密带 authVersion，冲突保留输入。

不能停用自己或修改自己的登录角色；停用/降级最后一个已启用 ADMIN 被拒绝。状态维护按固定顺序锁定账号，并从锁定的当前记录计数，避免 MySQL REPEATABLE READ 的历史快照导致两次并发操作各自误以为还剩管理员。密码重置允许当前管理员操作自身，但会使当前会话失效，界面明确说明。

V77 仅增加 admin_users.auth_version BIGINT NOT NULL DEFAULT 0，旧账号、哈希和状态不变；旧 JAR 忽略新增列。精确 blob 186aa5ca393b00b9392961f673373a56f5e66f99 已审查登记。旧版本并行兼容，JAR 回滚保留新增列。停用/改密/登录角色维护只在用户明确保存时增加版本；密码与企微登录均通过原 AdminUserService 获得带版本 principal。凭据擦除后仍保留版本；每次受保护后台请求都校验数据库账号状态、角色与版本。老式 principal 仅在版本为0且角色/状态匹配时兼容。

服务响应与审计不含密码及密码摘要；密码仅写入 BCrypt 哈希，创建/改密 DTO 的 toString 也脱敏；接口/页面 no-store。禁用、改密、登录角色维护的旧会话在下一次受保护请求被撤销。401 后界面明确要求重新登录，不把刷新失败说成保存失败。

验证：真实 V63/V68/V69/V77 在 H2 MySQL 模式运行；事务测试验证显式角色、密码哈希、失败回滚、版本、权限、无角色拒绝启用、自我保护、最后管理员及并发互停。过滤器测试验证凭据擦除后版本、旧 principal 兼容、禁用与角色变化、HTTP 401/跳转和会话失效。Chromium/WebKit 用例检查真实脚本的请求体、CSRF、冲突保留输入、自我停用控件、只读和移动布局。完整 Java clean package 通过；浏览器由 Linux CI 执行。

本轮未修改生产账号、配置或凭据，未部署；员工真实登录验收独立保留。
