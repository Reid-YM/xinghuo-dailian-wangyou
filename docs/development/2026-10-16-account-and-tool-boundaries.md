# 账号、辅助模块与开发工具核对

## 账号边界

源码核对结论：员工后台使用 admin_users；BootstrapConfig 仅在首次初始化且配置安全密码时建立管理层恢复账号，企业微信绑定服务可建立受控员工账号。组织工作台扩展员工档案、岗位和角色。原迁移方案明确保留 Spring Security Session、CSRF 和 legacy ADMIN/OPERATOR，未要求另建账号/密码体系。

旧 AccountAdminApiController 操作 accounts 网站会员，不是 admin_users。此前新版首页 O04 文案误称旧后台可以管理后台密码和登录角色，现更正为“账号与登录安全”并提供受 employee:view 保护的新页面。页面只展示本人名称、授权模式、数据范围及现有入口，不查询或返回任何凭据。

本轮不新增后台账号创建/重置密码功能，不更改认证或启用策略。员工档案及 RBAC 仍在新版组织工作台管理；网站会员、社区/投稿、测试反馈、首页展示位和 CRM 辅助工具沿用旧入口。这些辅助模块不属于 docs/xingwei-admin-migration.md 的 V3/V4 原生迁移优先项，不将其标为已原生迁移；旧后台必须继续保留。

## 字典与代码生成评估

scaffold-master 的字典/参数与当前站点配置、游戏/分类资料和固定组织岗位存在重叠。现有受控页面已经覆盖当前参数维护需求，暂不引入可随意修改业务状态枚举的第二套字典。

代码生成依赖参考项目的 MyBatis/JWT 模型，当前项目采用 JPA/JdbcTemplate、Flyway、Session 和数据范围守卫。直接移植会生成绕过现有审计和权限的数据访问路径。本轮不将其引入生产。未来若引入开发生成器，输出仍须通过本仓库权限、迁移哈希和 PR/CI 验证。

以上是原计划“评估”的结论，不代表已实现字典后台或代码生成器。
