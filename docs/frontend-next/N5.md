# Frontend Next N5：个人中心业务闭环

## 目标

在 N4 已接入真实账号会话、账号密码登录、微信开放平台登录和小程序扫码登录的基础上，让 `/next/account` 直接使用现有账号级业务接口查看真实询价、订单、服务进度、来源询价和售后状态，并把历史订单认领迁入 Frontend Next。

## 复用的现有后端

- `GET /api/console/summary`
- `GET /api/console/quotes`
- `GET /api/console/quotes/{businessNo}`
- `GET /api/console/orders`
- `GET /api/console/orders/{businessNo}`
- `GET /api/account/orders/candidates`
- `POST /api/account/orders/claim`

本阶段不新增数据库迁移，不建立第二套询价/订单数据源。

## 页面能力

- 显示当前账号真实询价总数、订单总数、进行中订单数。
- “我的订单”读取账号级订单列表，展示服务、状态、真实进度和更新时间。
- 点击订单后读取账号级订单详情，包括服务时间线、来源询价、售后问题及公开客服回复。
- “询价记录”读取当前账号全部询价，点击后查看游戏、需求、平台、期望时间、状态、当前进度和用户补充。
- 历史订单候选继续只显示脱敏业务编号，不在页面泄露完整单号。
- 历史订单认领要求用户主动输入自己保存的完整订单号/业务编号并再次确认；服务端重新校验订单状态与已验证联系方式。

## 安全与数据真实性

- 所有动态业务内容使用 DOM API / `textContent`，不使用 `innerHTML`。
- 不在 localStorage / sessionStorage 保存订单、询价或身份信息。
- 不生成演示金额，不补齐服务端未返回的进度、时间线或售后状态。
- 未验证联系方式时，历史订单候选与认领功能保持关闭。
- 认领写请求携带 `X-Requested-With`，并且只有用户明确点击且二次确认后才发送。
- 订单/询价详情继续由现有 `@RequireAccount` 和 `customer_account_id` 约束账号数据范围。

## 回退

N5 是独立 `/next/n5.js` runtime。移除 N5 runtime 后：

- N4 真实账号中心仍可用；
- N4 小程序/微信登录仍可用；
- N3 真实询价仍可用；
- 旧 `/account` 账号中心仍可完整回退；
- 新版后台不受影响。

## 下一步

N5 基础业务查看和历史订单认领稳定后，继续迁移“询价补充说明、订单补充说明、提交售后问题、售后追问”等已有账号接口，并做一次 Frontend Next 与新版后台业务字段总联调。
