# V4D 售后连续回复

V4C 的处理动作必须切换状态，因此客服无法在“处理中”继续向客户同步进展。V4D 允许 `order:manage` 在 `IN_PROGRESS` 或 `RESOLVED` 保持当前状态并追加明确的 `customerReply`；同状态动作若没有公开回复仍返回 400。内部处理说明保持必填，`expectedVersion` 继续防止并发覆盖。动作写入 V71 当前状态、V72 事件和审计；版本号递增。只读员工仍不能处理。

客户订单详情沿用归属校验，在 `afterSalesCases` 每条记录新增按事件 ID 正序排列的 `replies`，只包含回复时的状态、公开正文和时间。原 `customerReply` 字段保留为最新公开回复，供旧页面兼容。客户接口不读取内部处理说明、处理人或无公开回复的事件；个人中心将多条回复作为纯文本按时间展示。旧备注历史和旧的售后记录字段保持兼容。

没有新增数据库迁移或生产配置。V3H 小程序微信支付 PR #384 和企业微信写入 PR #372 仍独立待验收，真实收款关闭；本阶段不自动退款或改变订单履约状态。发布须经过 main PR、双 CI、`deploy/production` 的 `.deploy-request` 与 18080/8081/8080 门禁。
