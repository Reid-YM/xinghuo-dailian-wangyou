# 微信支付关闭入口终态保护

## 问题与行为

关闭支付单原实现仅拦截 CAPTURED，并对 CANCELLED 幂等返回；REFUNDED、FAILED 或未知状态仍会请求微信查单与关闭。最终数据库 UPDATE 只允许 CREATED/APPROVED，但接口无条件返回关闭成功，可能出现“界面显示已关闭、数据库仍已退款”的不一致；查单返回 SUCCESS 时还可能误报已支付。

本次在锁定支付单后，仅允许 CREATED/APPROVED 进入微信关闭流程。已支付仍拒绝关闭；已关闭仍幂等返回；已退款、失败或未知状态在请求外部接口之前拒绝并要求核对交易。权限、数据范围、If-Match、CSRF 与审计协议保持原有行为，账号和游客订单共享此关闭入口。

对允许关闭的待支付单仍先查单，发现真实到账则记账并返回 CAPTURED，不调用关闭；未付款则等待微信关闭成功后才记为 CANCELLED。微信请求失败保留待支付状态，不伪报已关闭。

## 验证

新增回归覆盖终态/未知态拒绝且不调用微信、已关闭幂等与已支付拒绝、CREATED/APPROVED 正常关闭、查单发现到账、关闭请求失败保留原状态。使用隔离 H2 数据库与模拟微信 SDK，无真实商户请求。

无数据库迁移、生产配置、支付开关、权限或认证变更。恢复本提交前实现可以回滚，但会重新暴露关闭结果与终态不一致的问题。
