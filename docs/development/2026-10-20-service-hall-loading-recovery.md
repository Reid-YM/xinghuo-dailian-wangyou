# 服务大厅读取中卡住：慢请求恢复

## 问题与复现

用户截图显示服务大厅一直停留在“正在读取服务目录”。本次只读公网打开可显示 41 个真实服务，不能据此排除慢网问题。源码中 N2 将分类和服务请求放在同一个 Promise.allSettled 后统一渲染，两个请求都没有截止时间；任一连接或响应 JSON 读取挂住，就会阻止已成功返回的数据展示。

在修改前的实际运行器上挂起 `/api/catalog`，同时正常返回 `/api/services`，等待服务卡片的浏览器断言超时，复现这一机制。该证据不等于追溯了截图时的服务器网络日志。

## 修复

- `/api/catalog`、`/api/services` 分别提交读取结果；真实服务先返回即可展示，不再等分类请求完成。
- 分类返回后补齐名称、筛选项和询价选项，保留 URL 筛选状态。
- 每个请求 10 秒截止时间覆盖连接和 JSON 内容读取，超时会中止请求并显示错误与“重新读取”。即使底层请求忽略中止，也能结束本次等待。
- 重新读取取消旧的一批请求；请求序号保护阻止迟到结果或旧状态覆盖当前数据。
- 请求失败时保留已成功读取的真实服务，不引入演示商品或价格。首次失败显示明确提示。
- 增加加载状态和 aria-busy；询价选项在数据未完整读取时继续禁用，仍由原服务端、权限和金额确认流程处理业务写入。

修改仅涉及 `next/n2.js`、对应契约与新增浏览器测试；N2 资源继续采用独立内容指纹，无新接口、数据库迁移、环境变量或权限变更。上一批 PR #602 会随正式主线一并发布。

## 验证范围

新增 Chromium / WebKit 回归覆盖：

1. 分类请求挂起时先展示服务；分类恢复后筛选和询价选项恢复，320px 无横向溢出，支持 `/services` 与 `/next/services`。
2. 请求完全挂起，以及响应头已收到而 JSON 读取挂起，均在截止时间内退出读取中；重试能够恢复。
3. 连续刷新时旧结果不覆盖新服务；刷新失败保留上一次真实服务。
