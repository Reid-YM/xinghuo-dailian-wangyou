# N29 第三阶段 · 窄屏长文本溢出保护

## 发现的缺口

N23–N28 各路由已有响应式布局，但真实业务中可能出现很长的无空格内容，例如业务编号、武器/攻略标题、投稿正文、客服渠道、法律原文中的网址。此类文本可能迫使 CSS Grid/Flex 子元素超出屏幕，从而造成横向滚动或按钮不可点。

## 本次修改

- N23 攻略中心：卡片、标题、空态允许长内容换行。
- N24 工具站：武器行、进度项及异常状态允许无空格内容安全折行。
- N25 投稿工作台：草稿预览、投稿列表、错误消息和多列面板避免固定最小宽度撑开屏幕。
- N26 业务记录：记录编号、状态卡片与统计栏允许长文本换行。
- N27 信任中心：真实案例、客服/信任配置、FAQ 等文本不撑开网格。
- N28 法律内容：正式规则/隐私页安全重建的正文和链接可以在窄屏换行。
- 仅新增 CSS `min-width:0` 与 `overflow-wrap:anywhere`，不修改后端业务响应、不隐藏溢出内容，也不截断法律原文。

当前 N23–N29 组合 CI 目标主线：`e1a15c664f25bef3b39154f2258f2d11314b90e1`；仅在 CI 全绿后才标记为阶段验收通过。

## 浏览器验收

`FrontendNextN29LongContentMobilePlaywrightTest` 从实际阶段运行时抽取 CSS，与现有 Next 预览基础样式一并装载。在 Chromium 和 WebKit 的 320px、390px 视口，为六类页面注入超长无空格用户/已发布内容，检查 `documentElement.scrollWidth` 没有超过视口宽度。静态合同断言每个阶段具有换行及 Grid/Flex 收缩保护。

本测试专注窄屏长内容布局，不冒充完整业务场景端到端验收。完整 N29–N30 仍需核心交易流、未登录状态、真实错误/重试及正式灰度切换前验收。

## 安全和发布边界

- 新分支叠加于 N29 第二阶段，属于尚未发布的 `/next/**` 预览体系。
- 不修改正式 Legacy 页面、默认路由开关、API、数据库、订单和支付。
- 先通过最新 main 的 Java/Maven 与 Chromium/WebKit 组合回归，再恢复阶段叠加 PR；不自动合并部署。
