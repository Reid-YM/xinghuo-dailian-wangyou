# 2026-10-17 订单报价与微信收款闭环

## 背景

生产环境已经完成网站微信 Native 支付的商户号、AppID、商户 API 证书、微信支付公钥、APIv3 密钥和 HTTPS 回调配置验证。启用 `WECHAT_PAY_ENABLED=true` 后应用可正常启动，`/api/wechat-pay/notify` 已注册；手工伪回调因缺少 `Wechatpay-*` 签名头被应用拒绝。

现有新版支付工作台实际上已经具备最终金额建单后端和前端逻辑，但“确认订单金额”区域仅在 `payment:manage` 且真实收款开关开启时出现。只读账号或开关关闭时页面会直接隐藏整个报价区域，运营人员容易误以为后台没有报价功能。

## 本阶段目标

1. 把“最终报价 / 开放支付”入口固定显示在新版支付工作台，不再因为权限或开关状态整个消失。
2. 明确展示真实收款开关和 `payment:manage` 权限状态，不降低现有 RBAC 边界。
3. 支持 `/admin/xingwei/payments?order=<订单号或业务编号>` 深链，进入页面后自动读取订单。
4. 保留“客服确认最终金额后建立待支付单”的人工审核语义，不引入商城自动定价或自动扣款。
5. 将缺少微信回调签名请求头的探测请求从 `500 PAYMENT_ERROR` 改为 `400 INVALID_CALLBACK`，避免把无效请求误报为支付服务故障。

## 安全边界

- `payment:view` 仍只允许查看支付记录和订单支付资格。
- `payment:manage` 才允许建立或关闭待支付单。
- 金额继续由客服显式录入，浏览器不能绕过后端订单归属、业务范围、金额校验和并发 revision 校验。
- 二维码生成、微信回调验签和 `CAPTURED` 到账判定逻辑不变。
- 本阶段不修改 `WECHAT_PAY_ENABLED`，不包含生产部署，也不切换 Frontend Next 为正式站点。

## 变更

- `admin-xingwei-payments.html`
  - 页面改名为“订单报价与微信收款”。
  - 报价区域固定显示并增加权限/开关状态提示。
  - 增加订单工作台返回入口和更明确的到账说明。
- `admin-xingwei-payments.js`
  - 报价区域不再因只读权限或开关关闭直接消失。
  - 只读账号仍可读取订单支付资格，但不能显示写入表单。
  - 支持 `?order=` 自动读取订单。
  - 保持 If-Match、CSRF、关闭前服务端复核和支付权限门禁。
- `WeChatPaymentErrors`
  - `MissingRequestHeaderException` 返回 `400 INVALID_CALLBACK`。
- 测试
  - Playwright 覆盖报价入口可见性、只读/关闭状态与订单深链。
  - 单元测试覆盖缺少微信签名头时的 400 分类。

## 后续验收

合并并按既有发布门禁部署后：

1. 使用具备 `payment:manage` 的管理员账号打开新版支付工作台。
2. 读取一个已绑定测试账号的履约订单。
3. 建立 `0.01` 元待支付单。
4. 测试账号在个人中心生成 Native 二维码。
5. 微信扫码实付并确认回调验签成功、支付状态最终为 `CAPTURED`。
6. 重复回调不重复记账；未支付关闭和超时恢复按既有逻辑验证。
