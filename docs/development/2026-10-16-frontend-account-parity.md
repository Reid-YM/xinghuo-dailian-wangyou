# 完整替换前的账号与询价功能对齐

- N6 头像通过既有 multipart API 上传，后续昵称写入使用服务器返回的头像地址；上传已成功而资料/刷新失败时明确区分，避免重试重复上传。
- 回访联系方式使用既有账号 API，展示服务端脱敏结果，新增/移除有忙碌和失败输入保留；不作为登录凭据。
- N5 增加云端工具存档、收藏分页与取消、投稿状态分页与受控撤回，投稿编辑使用现有专属 /account/submit 页面。所有读取继续由原账号归属校验保护；没有第二份数据模型。
- 订单详情显示完整公开客服回复及本人补充，保留既有售后动作。
- Native 支付单展示复用原受保护 API：只显示服务端金额与状态；用户明确点击后才请求二维码；只认 CAPTURED 为成功。离开详情/页面停止轮询，关闭功能时说明不可用；不改支付开关、不自动发起交易，不把 UI 回归当作真实收款验收。
- 登录支持同站安全回跳，拒绝外站、后台/API、注销和认证循环目标；注册保持当前正式/并行 URL 命名空间。
- 邮件重置 token 与六位码两种原服务端流程均可用；token 只在内存消费并从地址栏移除，不进入存储。原邮箱验证链接也沿用既有接口，不遗失已发送链接。
- N3 补齐截图附件：上传失败保留需求，重试复用已成功上传的 assetId 和原 Idempotency-Key；提交成功清空已绑定附件，避免下一次提交误复用。移除原本未发送到后端的“称呼”输入。

浏览器检查覆盖头像 multipart 与服务器地址、回访失败/重试、存档/收藏/投稿、服务端支付状态、邮件 token，以及截图与询价重试；所有外部交易均使用 fixture，不执行真实支付或邮件。

本组无数据库或生产配置变更。完整迁移的后台辅助模块仍在清单中，不把本组完成记为整体完成；整体统一部署前保留旧版回退。
