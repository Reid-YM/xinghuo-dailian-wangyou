# 会员与运营迁移（待统一发布）

新增 `/admin/xingwei/operations`，从新版后台直接进入会员、评论/投稿、测试反馈、首页展示位、CRM。所有浏览器操作只调用 `/api/admin/xingwei/operations/**`，复用原有业务服务和 Spring 登录。

## 权限与数据范围

- 会员 `customer:view/manage`、反馈 `feedback:view/manage` 为新增权限；V76 只授予现有 XW_MANAGEMENT 角色，其他既有角色不自动扩权。
- 评论/投稿沿用 `content:view/manage`；展示位沿用 `site:view/manage`。
- 上述全站数据必须同时有全部数据范围；部门/个人角色不会得到全站数据。
- CRM 沿用 `quote:view/manage`，SQL 在计数与分页前执行原有业务归属范围。
- 特殊会员角色的维护、会员物理删除只允许现有恢复 ADMIN；删除必须输入准确的会员公开编号。

## 写入保护

所有已有记录写入要求 If-Match，事务内锁定原记录并核对数据库微秒时间戳的摘要。冲突返回 409 并保留表单输入。改密及会员停用撤销现有会员会话；审计不含密码。会员 DTO 不返回密码摘要，登录日志不返回原始地址。投稿只能关联实际已发布攻略，不能把改状态伪装成发布正文。附件先校验版本再存储，并通过受权限保护的地址读取。

沿用业务服务的校验及审计；新增的会员/社区动作补充原生审计。对审计失败执行事务回滚。全部运营页和 API 返回 no-store。

## 数据库审查

V76 为新增四项权限及现有管理角色的四项关系，没有删除、字段修改、会员/订单/认证凭据数据写入；与旧 JAR 并行兼容。精确 blob `90ecc8061fa553b570b4e025e39321fa422ce579`，已登记发布清单，并用真实 V63 + V76 在 H2 MySQL 模式执行验证授予范围。JAR 回滚保留新权限记录，不需要删除权限。

## 验证与限制

服务测试覆盖真实 SQL、部门/个人 CRM 范围、敏感字段排除、LIKE 字面搜索、版本冲突、会员会话撤销调用、审计失败回滚、特殊角色与删除确认保护。浏览器测试覆盖 CSRF/If-Match、冲突保留输入、全部模块、真实脚本、移动端布局、读取失败恢复。浏览器 fixture 不证明真实员工业务验收。

本轮不部署。首页推荐位在新版前台的公开配置呈现仍在完整迁移清单中，不能仅因运营编辑器完成就宣称端到端展示已完成。员工账号生命周期和后台默认入口等剩余项继续开发。
