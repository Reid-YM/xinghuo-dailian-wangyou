# V6A 完整迁移交付核验

V6A · UNIFIED DELIVERY 表示运行包的功能范围，部署前不声明生产替换已完成。沿用用户“整体开发完成后统一部署”的授权，本轮不逐 PR 发布，不因状态文案再做第二次部署。

## 默认入口与功能完整性

- `/admin` 进入 `/admin/xingwei`；原管理菜单均有原生工作台，详见 [入口清单](2026-10-16-complete-migration-plan.md)。普通员工只能走新版授权接口；`/admin?legacy=1` 与旧 API 仅供恢复 ADMIN。
- 正式首页、服务、询价和账号核心路径使用新版运行时，路径、刷新、历史前进后退及登录回跳正确。服务详情、游戏 SEO 页、攻略、业务记录、工具、联系与投稿编辑继续使用既有专用原生页面，从正式导航进入，不依赖旧后台或演示行为。
- 公共详情使用服务 slug / 游戏 seoSlug；无游戏 SEO 地址时进入实际服务筛选，避免用内部编码访问详情而 404。
- 后台首页、API health、业务版本、更新记录与测试统一为 V6A，页面发现运行版本不符时继续明确告警；页面 no-store，修改过的后台脚本更新资源版本，Next 运行时按实际内容摘要更新 URL。
- 表单冲突不刷新草稿；原账号拦截器、Spring Security、CSRF、模块权限与数据范围保留。简版与完整目录编辑共用版本，连续保存使用最新服务端对象。

## 修复“替换无效”的依据

1. 真实账号请求必须使用服务端要求的 `X-Requested-With: fetch`，浏览器请求经过实际拦截器验证。
2. 真实正式路径转发到新版，而非只新增 `/next` 预览；发布冒烟检查实际 X-Xinghuo-Frontend 与摘要脚本，并检查明确旧版回退。
3. 真实公开服务 DTO 使用小写价格模式，统一比较后再显示价格，不使用伪造大写 fixture 自证。
4. 读取真实配置/服务，失败显示重试；首页无演示商品，询价 HTML 未加载时显示待读取，不先展示模拟选择。
5. 提交先读取 FormData，再禁用控件；工具资料保存后重新绑定服务端对象；目录保存拒绝旧版本及发布绕过。
6. `FrontendPatchDebtContractTest` 保证退休的 ui-fixes 不恢复；`AdminResiliencePlaywrightTest` 保留缺失面板和程序触发空白后的恢复测试，新版导航另有手机/桌面及版本漂移检查。

## 数据库与外部边界

当前集中交付相对 V5A 仅增加 V76/V77：前者增加 customer/feedback 权限点且只默认授予 XW_MANAGEMENT，后者给 admin_users 增加 auth_version 默认 0。精确 SQL 与 blob 由审核清单及 ReviewedFlywayMigrationContractTest 锁定。历史迁移不改写，新增列与原凭据/启用状态兼容；JAR 回滚不撤销已执行的 migration。

真实支付/退款、企业微信外部写入和真实员工/小程序验收继续独立；fixture、CI 和端口冒烟不能替代这些验收。不为完整迁移而打开支付开关或执行真实资金/目录操作。
