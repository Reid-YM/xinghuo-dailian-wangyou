# Frontend Next 并行上线方案

当前分支：`frontend-next`

## 目标

采用与新版后台 `/admin/xingwei` 类似的并行演进方式：旧前端继续在线，新前端先以独立入口上线，边开发边联调，成熟一页替换一页，并保留旧版回退能力。

## 独立入口

- `/next`：新版首页
- `/next/services`：新版服务大厅
- `/next/quote`：新版询价
- `/next/account`：新版个人中心

当前四个入口由同一个 Frontend Next 壳层承载，旧 `/`、`/services`、`/quote`、`/account` 保持不变。

## 当前阶段

- N1：四页视觉 / 动效 / 响应式基线完成。
- N2：已开始只读接入现有 `GET /api/catalog` 与 `GET /api/services`。
- N2 接口成功时服务大厅展示真实公开目录；失败时自动保留 V1 静态回退。
- 新版询价选择项开始读取公开目录，但提交按钮仍为演示模式，不调用生产写接口。
- 个人中心目前仍为演示数据，后续再接账号会话和真实只读记录。

详细 N2 设计与边界见 `docs/frontend-next/N2.md`。

## 当前边界

- 不替换 `/`
- 不修改旧 `/services`、`/quote`、`/account`
- N2 不写生产询价或订单数据
- 不改变真实订单状态
- 不在新前端写死客服联系方式
- 暂不把演示数字视为真实业务数据

## 后续顺序

1. N1：视觉/动效/响应式基线 ✅
2. N2：服务大厅只读接入游戏、分类、服务数据 ✅（当前）
3. N3：新版询价真实提交与失败恢复
4. N4：账号会话、微信扫码登录、个人中心只读数据
5. N5：订单/进度真实数据与前后台总联调
6. N6：按页面逐项将旧导航切向 `/next/...`
7. N7：全部回归稳定后，再评估 `/` 默认首页切换

## 动效原则

- Sticky Navigation
- 页面切换淡入
- Hero 层次/轻视差方向
- 卡片 Hover Elevation
- 服务筛选过渡
- 询价实时摘要
- 后续补 Scroll Reveal、Reduced Motion 与真实素材替换

## 安全策略

`/next` 与 `/next/**` 单独加入公开路径；现有旧前端公开路径保持不变。V1 页面内脚本通过精确 CSP SHA-256 hash 放行；N2 运行时为同源 `/next/n2.js`，只读取现有公开 API，不开启全局 `script-src 'unsafe-inline'`。
