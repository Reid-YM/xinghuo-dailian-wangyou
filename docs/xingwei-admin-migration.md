# 星维管理后台迁移方案

## 目标

以 `wbr664393425-lgtm/scaffold-master` 的后台信息架构、组织权限和交互设计作为参考，在不推倒现有线上系统的前提下，将星火网游现有后台逐步升级为“星维网络服务工作室管理后台”。

## 核心原则

1. 不直接替换当前 `/admin`，新版入口使用 `/admin/xingwei` 并行运行。
2. 不引入第二套认证。继续使用现有 Spring Security Session、管理员账号、CSRF 和角色边界。
3. 不把 scaffold-master 的 MyBatis/JWT 数据层直接合并进现有 JPA/Flyway 项目。
4. 数据库变更只通过新的 Flyway migration 进入，并保持向后兼容。
5. 所有生产变更继续走 GitHub Pull Request、CI、生产部署门禁和可回滚 release。
6. 先迁移通用组织权限，再迁移询价、订单、派单和微信支付等高业务耦合模块。

## 阶段

### V1：并行管理入口

- `/admin/xingwei` 新版后台入口。
- 复用现有管理员登录与退出。
- 复用旧后台的询价、订单、服务、SEO、审计等功能入口。
- 新增后台健康检查 `/api/admin/xingwei/health`。
- 桌面端固定侧栏，移动端抽屉导航。
- 模块快速搜索。

本阶段不改数据库，不改变现有前台和旧后台行为。

### V2：组织、岗位、角色和数据权限

计划新增（以最终 Flyway 迁移为准）：

- `admin_department`：部门/中心。
- `admin_post`：岗位。
- `admin_staff_profile`：后台员工资料，与现有管理员账号关联。
- `admin_role`：业务角色。
- `admin_permission`：菜单/操作权限点。
- `admin_staff_role`：员工角色关系。
- `admin_role_permission`：角色权限关系。
- `admin_data_scope`：按全局、部门、本人等范围约束可见数据。

首批组织预置：

- 管理层：负责人 / 店长。
- 运营中心：淘宝运营、闲鱼运营、商品/活动运营、内容设计/美工。
- 客服与订单中心：售前客服、售后客服、订单调度/派单。
- 游戏服务中心：代练/陪玩等执行岗位。
- 技术中心：网站与系统维护。

V2 仍保留现有 `ADMIN` / `OPERATOR` 作为底层安全兜底，细粒度权限在应用层叠加，确认稳定后再收敛旧角色模型。

### V3：业务迁移

优先级：

1. 询价与客户线索。
2. 订单与履约。
3. 派单与员工工作台。
4. 服务项目与游戏资料。
5. 售后与异常单。

每个模块迁移时采用“新页面调用现有服务层/仓储层”的方式，避免重复建表和双写。

### V4：渠道与微信能力

- 网站微信登录与小程序账号互通状态。
- 微信支付订单、回调、退款和异常对账。
- 淘宝/闲鱼运营任务与状态汇总。
- 官网与渠道的服务状态统一配置。

## scaffold-master 能力映射

| scaffold-master | 星维落地方式 |
| --- | --- |
| 用户/角色/部门/岗位 | 参考其模型，在现有 JPA/Flyway 内重新实现 |
| 菜单/按钮权限 | 参考 RBAC 思路，叠加到现有 ADMIN/OPERATOR 安全边界 |
| 数据范围 | 用 JPA 查询条件/服务层约束实现，不直接移植 MyBatis 拦截逻辑 |
| 登录/操作日志 | 优先复用现有审计表，再补权限溯源视图 |
| 字典/参数 | 评估与现有站点配置是否重复后再引入 |
| 代码生成 | 仅作为开发工具评估，不进入第一阶段生产链路 |
| Vue 3 前端 | 视觉/交互作为参考；第一阶段先使用现有 Thymeleaf 资产，避免同时替换整个前端构建链 |

## 发布和回滚

开发分支：`feat/xingwei-admin-v1`

生产流程继续遵守仓库现有规则：

1. 功能分支提交。
2. Pull Request 到 `main`。
3. PR CI 全部通过。
4. 合并到 `main` 后再次通过 main CI。
5. 才允许触发生产部署。
6. 生产冒烟测试失败时使用现有 release/symlink 回滚机制。

## 当前 V1 验收项

- 未登录访问 `/admin/xingwei` 仍进入现有管理员认证流程。
- `ADMIN` / `OPERATOR` 可访问新版入口。
- `/api/admin/xingwei/health` 受 `/api/admin/**` 保护。
- 旧 `/admin` 完全不受影响。
- `/admin/guides`、`/admin/frontend-controls` 等原页面可从新版入口继续访问。
- PC、窄屏、手机布局均不出现横向溢出。
- CSP 不需要新增 `unsafe-eval` 或第三方脚本源。
- 不新增数据库 migration。
