# V3R 统一交付核对

V3R 汇集三条独立开发线，经各自 PR 与 Java/Maven、Chromium/WebKit CI 验证后进入主线：

- PR #404：星维业务工作台异常订单独立队列。`order:view` 与 ALL / DEPARTMENT / SELF 数据范围由后端执行；客户说明和内部备注分别显示。
- PR #405：客户个人中心售后问题说明。服务端校验订单归属、类别、长度和 `customer_note` 剩余容量，记录审计；原有订单补充说明同样加上容量保护。
- PR #406：服务大厅读取失败时保留服务端已有卡片并提供重试；筛选无结果时提供清除入口，补充筛选状态和搜索框可访问性。

## 发布边界

这次没有新增 Flyway migration，也没有修改生产配置。客户提交售后问题不会自动取消订单、改变履约状态或发起退款。V3H PR #384 小程序微信支付继续未合并、真实收款关闭；PR #372 企业微信写入继续独立验收；迷彩追踪器 1.0.14 的备案及真机云同步测试暂缓。

## 发布与复核

统一发布仍按 `main` PR、完整 CI、`Deploy Production` 工作流和 `deploy/production` 的 `.deploy-request` 流程执行。生产预发布 18080、canary 8081、正式 8080 任一门禁失败即停止切换或使用现有 release/symlink 回滚。

发布后检查公开首页与服务大厅、服务大厅失败/空结果恢复、后台匿名访问拦截、星维运行版本与页面版本一致性。需要登录态和真实订单数据的异常订单、售后提交由授权账号做后续人工验收；不使用生产真实支付来验证本版。
