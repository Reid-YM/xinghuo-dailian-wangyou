# Frontend Next N6：账号设置与安全闭环

## 目标

在 N4/N5 已完成真实账号登录、业务查看与业务写操作的基础上，把旧账号中心中的核心账号安全能力迁入 `/next/account`，为后续判断是否具备替换旧 `/account` 的条件做准备。

## 复用的现有后端

- `POST /api/account/profile`
- `POST /api/account/email/verify/request`
- `POST /api/account/email/verify/confirm`
- `POST /api/account/password/change`
- `GET /api/account/sessions`（数据由 N4 已读取）
- `DELETE /api/account/sessions/{id}`
- `POST /api/account/sessions/revoke-all`
- `GET /api/account/security/events`（数据由 N4 已读取）

本阶段不新增数据库迁移，不建立第二套账号安全模型。

## 页面能力

### 账号资料

- 可修改昵称，最长 60 个字符。
- 修改昵称时保留账号当前头像地址，不因本次保存被清空。
- 头像文件上传暂继续由旧账号中心保留，后续可作为独立小步迁移。

### 安全邮箱

- 显示当前邮箱和是否已验证。
- 支持向指定邮箱发送验证码。
- 支持在 Frontend Next 中输入验证码完成验证。
- 验证码最长 12 位，页面提示不要向他人提供验证码。

### 修改密码

前端提示并对齐服务端密码策略：

- 至少 8 位；
- 小写字母 / 大写字母 / 数字 / 符号至少包含两类；
- BCrypt 有效输入上限由服务端按 72 字节再次校验；
- 新密码不能与原密码相同。

提交前要求用户明确确认。服务端改密成功后会撤销该账号全部会话并清除当前登录 Cookie，因此页面随后重新读取账号状态并进入未登录界面。

### 登录设备

- 展示当前账号自己的有效会话、脱敏 IP、设备标签、登录时间与最近活动时间。
- 会话 ID 只作为请求句柄使用，不显示在页面文字中。
- 当前设备不提供单独“下线此设备”按钮，避免误操作。
- 其他设备可单独下线。
- 支持“一次下线其他全部设备”，服务端保留当前会话。

## 安全约束

- 所有写请求和 DELETE 请求继续携带 `X-Requested-With: XMLHttpRequest`。
- 请求使用当前账号的同源 Cookie 会话。
- 不使用 `innerHTML`、`localStorage`、`sessionStorage` 保存账号或业务数据。
- 单设备下线仍由服务端重新校验该 session 是否属于当前账号。
- 改密后的会话失效由服务端执行，不依赖前端模拟退出。
- 邮箱验证和密码强度均以服务端校验结果为最终依据。

## 回退

N6 是独立 `/next/n6-account-security.js` runtime。移除该 runtime 后：

- N5 询价/订单/进度/售后能力仍完整；
- N4 登录、微信开放平台、小程序扫码登录仍完整；
- 旧 `/account` 仍可作为完整账号中心回退；
- 新版后台不受影响。

## 后续替换前缺口

N6 完成后，旧账号中心仍至少有以下能力需要评估是否迁移：

1. 新用户注册；
2. 忘记密码 / 重置密码；
3. 头像文件上传；
4. 询价联系方式管理；
5. 全量移动端和异常降级总联调。

这些完成并通过总联调前，不切换旧 `/account` 路由。
